# GCP 10-Node Pilot (2026-09-14)

## Purpose

This pilot checks whether the current deployment can reproduce an existing WAN data point before running a wider cloud matrix. It is not a publication run: every protocol was run once, and two runs exposed liveness problems.

## Configuration

- GCP project: `shortfin`
- Code commit: `3fa44f8a62997a4ef95d2132518d12ad9b221d8b`
- Topology: 10 nodes in 5 zones, 2 VMs per zone
- Zones: `europe-west1-b`, `us-west1-a`, `asia-east1-a`, `us-east1-b`, `asia-southeast1-a`
- VM type: `n2-standard-2` (2 vCPU per VM)
- Faults: 1 silent node, leaving 9 active nodes
- Workers: 1 per node; primary and worker collocated
- Input rate: 120,006 tx/s (Wahoo reports 120,000 tx/s)
- Transaction size: 512 B
- Requested duration: 50 s; benchmark startup delay: 20 s
- Header size: 1,000 B; maximum header delay: 1,000 ms
- Batch size: 500,000 B; maximum batch delay: 200 ms
- GC depth: 50 rounds; sync retry delay: 10,000 ms; sync retry nodes: 3
- Consensus protocol setting: `round_robin`

| Protocol | Run validity | Observed commit span | Consensus TPS | Consensus latency | End-to-end TPS | End-to-end latency |
|---|---|---:|---:|---:|---:|---:|
| Narwhal/Tusk | Valid | 52 s | 100,410 | 4,864 ms | 96,498 | 5,801 ms |
| Shortfin | Invalid: stalled | 33 s | 113,359 | 4,590 ms | 108,517 | 5,899 ms |
| Mahi-Mahi-5 | Valid | 54 s | 111,145 | 4,720 ms | 107,333 | 5,682 ms |
| Wahoo | Invalid: no committed payload | 0 s | 0 | 0 ms | 0 | 0 ms |

The parser's execution time is the span between committed records, not the requested benchmark duration. Therefore, Shortfin's TPS is computed over a shortened 33-second interval and must not be interpreted as sustained 50-second throughput.

## Historical Comparison

The historical files use the same 10-node, one-silent-node, 120k tx/s WAN configuration.

| Protocol | Run | Commit span | Consensus TPS | Consensus latency | End-to-end TPS | End-to-end latency |
|---|---|---:|---:|---:|---:|---:|
| Narwhal/Tusk | Historical | 46 s | 97,883 | 4,820 ms | 93,928 | 5,795 ms |
| Narwhal/Tusk | Current | 52 s | 100,410 | 4,864 ms | 96,498 | 5,801 ms |
| Shortfin | Historical (`noveldag`) | 47 s | 110,147 | 3,117 ms | 105,616 | 4,088 ms |
| Shortfin | Current, invalid | 33 s | 113,359 | 4,590 ms | 108,517 | 5,899 ms |
| Wahoo | Historical | 49 s | 118,114 | 2,046 ms | 117,243 | 2,859 ms |
| Wahoo | Current, invalid | 0 s | 0 | 0 ms | 0 | 0 ms |

Narwhal's current end-to-end TPS is 2.74% above the historical value, while latency differs by only 0.10%. Consensus TPS differs by 2.58% and consensus latency by 0.91%. This is strong evidence that the cloud topology, workload generation, worker path, and result parser reproduce the old environment closely.

Shortfin's end-to-end TPS happens to be 2.75% above the old value, but its latency is 44.30% higher and it did not cover a full commit window. The apparent TPS agreement is not a valid reproduction result.

## Failure Evidence

### Shortfin

- Every active primary logged 3,701 `Committed` records.
- Progress then stopped around rounds 57-58.
- Diagnostics show `parents_1=0`; one node reached only `6/7` round weight before later moving to round 58 and blocking again.
- The processes remained alive. The failure is protocol progress under WAN timing, rather than a VM crash.

### Wahoo

- Across the nine active primary logs, EPBC produced 243 proposals, 198 `Ts1` certificates, and 198 `Ts2` certificates/deliveries.
- There were no `Tf` deliveries. All nine primaries logged an internal round-3 leader decision.
- No payload-bearing block reached the generic committed-record stream, so measured TPS is zero.
- Every primary eventually stopped at round 5 with `move_count=6/7`.

This shows that the EPBC slow-broadcast stages execute, but the complete Wahoo ordering and commit pipeline is not live in this 10-node WAN run.

## Interpretation

1. The infrastructure is reproducible: Narwhal closely matches the old data.
2. Mahi-Mahi-5 completed the full window and provides a usable first cloud data point, although no historical Mahi-Mahi result exists for comparison.
3. Shortfin and Wahoo must be treated as diagnostic runs only. They should not be plotted or used in paper-level protocol comparisons.
4. No protocol code was changed after this pilot, by request.
